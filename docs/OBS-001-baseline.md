## Observed passing invariants

- Read results and returned SHA-256 revisions agree with exact UTF-8 file bytes, including BOM/CRLF and long notes.
- Filesystem create refuses an existing target; replace/append/heading/frontmatter/delete/move reject missing and stale revisions without changing original bytes.
- Create/replace/append preserve supplied bytes. Heading edits preserve the prefix and following section, including BOM/CRLF. Frontmatter edits preserve comments, values and exact body; see B02 for YAML formatting.
- Ambiguous/missing/out-of-range heading selection and invalid YAML frontmatter patches do not write; metadata rejects invalid YAML.
- Two backend instances sharing the same vault/cache produce exactly one successful replacement; the loser receives CONFLICT, and the winner's revision matches the complete final file.
- Injected rename failure leaves original bytes/mode intact, removes the temporary file and releases the lock for a retry.
- Filesystem direct read/write traversal, static symlink escapes and canonical scope bypass attempts are denied. New descendants behind symlinks are covered.
- All 18 registered content mutation tools reject read-only calls (19 cases including write create/replace): write, bulk, append, heading/frontmatter, all nine canvas mutations, move, rename, delete, create-folder. Valid canvas inputs ensure validation errors cannot hide a bypass. Every seeded file remains byte-identical.
- Search excludes `.obsidian`, `.git` and static external symlinks when rebuilding. This does not imply read-scope enforcement: K03 is a confirmed exception.
